# RenPyTranslator 3.7.3 — «expected ':' not found» (menu)

## Что это за ошибка

    Parsing the script failed.
    File "game/c-x_edg01.rpy", line 24: expected ':' not found.
        menu

Ren'Py наткнулся на строку `menu` **без двоеточия**. Это не перевод и не
шрифты — это повреждённый файл скрипта: `menu:` превратилось в `menu`.
Игра не запустится, пока двоеточие не вернуть.

## Как починить за один клик

Вкладка **«Проверка и отчёт»** → кнопка **«Починить синтаксис»**.

Программа:

1. проходит по всем `.rpy` игры (кроме `tl/`),
2. находит строки-блоки без двоеточия (`menu`, `label`, `screen`, `style`,
   `translate`, `init python` — но только там, где блок действительно
   начинается),
3. возвращает `:` на место,
4. показывает контекст: две строки выше и две ниже — видно, откуда взялась
   поломка,
5. удаляет рядом лежащий `.rpyc`, чтобы Ren'Py перекомпилировал скрипт.

Копия файлов до правки остаётся в `game/tl/rt_syntax_backup/`.

Из командной строки то же самое:

    RenPyTranslator.exe --game "C:\Games\MyVN\game" --check-syntax
    RenPyTranslator.exe --game "C:\Games\MyVN\game" --fix-syntax

`--check-syntax` ничего не меняет и возвращает код 1, если поломка есть.

## Почему это возвращалось

Старая проверка считала строку битой только если **следующая** строка была
с отступом. Стоило телу меню съехать (или появиться между `menu` и телом
пустой строке с комментарием) — и `menu` оставался без двоеточия: «Починить
меню» сообщал, что всё хорошо, а игра падала на том же месте. Теперь `menu`
чинится всегда.

Вторая страховка: правка файлов игры «по координатам» (режим прямой замены)
теперь проверяет, что по сохранённым координатам лежит именно тот литерал.
Если файл изменился после разбора, строка пропускается с предупреждением —
вслепую в код больше не пишется.
