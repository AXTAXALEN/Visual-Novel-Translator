# RenPyTranslator 3.7.0 — экспорт на 100 000+ строк

## Что было

After Class: 101 000+ строк. «Экспорт текста для агента» собирал **три**
файла (txt, json, docx) и каждый — целиком в памяти: список из сотен тысяч
строк, потом одна склеенная строка, потом ещё словарь для JSON, потом
Word-документ. На таком объёме это зависание и вылет.

## Что стало

| Формат | Как теперь |
|---|---|
| **TXT** | Пишется потоком, строка за строкой. По умолчанию режется на части по 5000 строк: `renpy_translator_export-part01.txt`, `-part02.txt` … В шапке каждой части те же правила для агента. |
| **JSON** | Тоже потоком (по объекту на строку), файл остаётся валидным. Включается галочкой «ещё JSON». |
| **DOCX** | По умолчанию не создаётся. Выше 15 000 строк отказывается с понятным сообщением: Word держит документ в памяти, именно на нём программа и падала. |

## Цифры (проверено на синтетическом проекте)

* 101 000 строк → TXT: **1,2 с**, 21 часть по ~2,2 МБ, пик памяти 180 МБ.
* 20 000 строк → TXT 0,2 с (5 частей), JSON 0,3 с (11,5 МБ), валидность
  проверена `json.loads`.
* DOCX на 20 000 строках: не собирается, пишет предупреждение вместо
  падения.

## Как пользоваться

1. «Литературный текст» → «1. Экспорт текста для агента».
2. Галочка **«частями по 5000 строк»** включена — так и оставьте: агенту
   проще работать с куском, чем с файлом на 40 МБ.
3. JSON нужен редко (например, для своих скриптов) — включается галочкой.
   DOCX — только для маленьких глав.
4. После перевода: «2. Импорт правок в игру» → можно выделить **сразу все
   части** в диалоге выбора файлов, программа прочитает их по очереди.
5. CLI: `--export --format txt --split 5000`, при желании
   `--with-json`, `--with-docx`, `--format docx --docx-limit 40000`.
