# Что нового в 3.7.6

## Коротко

Перевод больше **не встаёт** из-за лимитов бесплатного Google.
Раньше на AfterClass (88 083 строки) программа перевела 2 972 строки и
остановилась: «50 строк подряд не переведены». Теперь в такой ситуации она
меняет адрес сервиса, затем движок, затем переходит в медленный режим — и
доводит перевод до конца.

## Что было в логе 3.7.4

```
Строк найдено: 88083  →  2972 новых, 71309 ошибок за 24 мин  (остановлено)
Причина: 50 строк подряд не переведены
```

71 309 «ошибок» — это не строки, которые нельзя перевести. Это ответы
Google `403` / `429` («слишком много запросов», «доступ ограничен»).
Программа на тот момент считала такие ответы приговором и останавливалась,
хотя уже переведённое аккуратно лежало в кэше.

## Что сделано

### 1. Три зеркала Google вместо одного адреса

Бесплатный движок теперь знает три адреса одного и того же сервиса
(`clients5.google.com`, `clients6.google.com`, `translate.google.com`).
Получил отказ — следующий запрос уходит на другое зеркало. В журнале видно
причину: `Google ответил HTTP 429 (clients6.google.com)`.

### 2. Цепочка движков: переключение вместо остановки

Если основной движок исчерпал себя, работа продолжается на запасном —
**с того же места**, без потери уже переведённого:

| Выбранный движок | Порядок работы |
|---|---|
| Google (бесплатный) | google → google-web → mymemory |
| DeepL | deepl → google → google-web → mymemory |
| LibreTranslate (если задан адрес) | libre → google → google-web → mymemory |
| mock / none | без запасных (это отладочные режимы) |

Каждое переключение пишется в журнал:

```
движок «google» ограничивает запросы (50 строк подряд не переведены)
  — переключаюсь на «google-web» и продолжаю
```

### 3. Медленный режим: «долго, но без потерь»

Если ограничения догнали все движки, программа не останавливается:

* один поток вместо четырёх;
* пауза между запросами от 2 секунд, при каждой неудаче удваивается (до 60 с);
* пачки по 25 строк, неудачная пачка возвращается в очередь и переводится на
  новом, более медленном темпе;
* каждые 100 строк в журнале прогресс: `Медленный режим: 1 200 из 8 400 готово`;
* сдаётся только если сервис не пустил **5 раз подряд** — тогда
  непереведённые строки сохраняются в `*.failed.txt` и подхватываются
  следующим запуском.

Сколько это займёт: примерно 2,5 секунды на 25 строк, то есть 80 000 строк —
около двух часов без участия человека. Можно свернуть окно и заниматься
своими делами; кэш пишется на диск по ходу.

### 4. Дожим стал умнее

После лимита программа сначала проверяет тремя пробными строками, ожил ли
сервис, и только потом запускает медленный проход. Мёртвый сервис больше не
занимает час времени.

### 5. Мелочи

* Кнопка «Отмена» теперь честно отражается в отчёте («остановлено
  пользователем»), а не «движок ограничивает запросы».
* Убрана нелепая арифметика в строке журнала об остановке.
* В настройках появился флаг `slow_mode` (по умолчанию включён). Если нужен
  быстрый отказ вместо долгого перевода — его можно выключить.

## Что делать с AfterClass прямо сейчас

1. Запустить 3.7.6 на той же папке игры (`C:\Visual Novels\AfterClass-…`).
   Всё, что переведено раньше, возьмётся из кэша — заново платить временем
   не придётся.
2. Дальше возможны два сценария, и оба рабочие:
   * Google ещё «дышит» — пойдёт быстро, как обычно;
   * Google заблокировал IP — увидите в журнале переключение на
     `google-web`/`mymemory` и строку «включаю медленный режим». Это нормально,
     программа работает, просто медленнее.
3. Про объём: 88 083 строки — это большая игра, но переводится она один раз.
   Кэш устроен так, что повторный запуск даёт «0 новых» и занимает секунды.
